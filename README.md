# PMB League Manager — Phase 1

Foundation build of the football league management app. Users, Leagues, and
Clubs are fully functional. Players, Transfers, Notifications, and Activity
Logs exist as database tables only, so later phases can be built on this
schema without breaking changes.

## Tech stack

- Next.js 14 (App Router) + React + TypeScript
- Tailwind CSS (black / gold / white dark theme)
- PostgreSQL + Prisma ORM
- Auth.js (NextAuth v5) with a Credentials provider
- bcryptjs for password hashing

## 1. Install dependencies

```bash
npm install
```

## 2. Configure environment

```bash
cp .env.example .env
```

Edit `.env`:

- `DATABASE_URL` — your PostgreSQL connection string.
- `AUTH_SECRET` — generate one with `openssl rand -base64 32`.

## 3. Create the database schema

```bash
npx prisma migrate dev --name init
```

This creates all tables: `User`, `League`, `Club`, `Player`, `Transfer`,
`Notification`, `ActivityLog`, `TransferWindow`.

## 4. Seed the data

```bash
npm run prisma:seed
```

This creates:

- 1 Administrator account
- 6 leagues (Premier League, La Liga, Serie A, Bundesliga, Ligue 1, VIP League)
- All 112 clubs across those leagues
- 1 Club Manager account per club, auto-linked to that club

## 5. Run the app

```bash
npm run dev
```

Visit `http://localhost:3000`.

## Architecture notes

- **Route protection is layered:** `src/middleware.ts` blocks `/admin/*`
  and `/manager/*` at the edge for unauthenticated users and wrong roles,
  and every layout/page under those routes re-verifies the session
  server-side before querying data. Manager pages never accept a club id
  from the URL — they always resolve the club from the signed-in session,
  so there is no URL to edit to reach another club's data.
- **Passwords** are hashed with bcrypt (10 rounds) and never stored or
  logged in plain text.
- **Scalability:** `Player`, `Transfer`, `Notification`, and `ActivityLog`
  tables already exist with the relations later phases will need (e.g.
  `Player.clubId`), so adding real functionality later is additive, not a
  schema rewrite.
- **Transfer window toggle** on the Admin Dashboard only flips a status
  flag (`TransferWindow.isOpen`) shown on both dashboards — it does not
  unlock any transfer logic yet, per the Phase 1 scope.

## What's intentionally NOT built yet

Player registration, transfers, notifications, statistics, and backups are
out of scope for this phase. The corresponding UI exists (empty states,
disabled-feeling buttons, "closed" status) but has no wired-up logic, and
the corresponding database tables exist but are otherwise unused.
